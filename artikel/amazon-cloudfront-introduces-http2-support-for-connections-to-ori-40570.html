Amazon CloudFront Introduces HTTP/2 Support for Connections to Origins

🌐 Source: Amazon • 📅 23 Nov 2026 • ⏱️ 1 min read (197 words, 📖 Standard)
💡 Key Takeaways
  • Amazon CloudFront now supports HTTP/2 connections to custom origins and VPC origins.
  • Sources indicate that until now, CloudFront connected to origins only over HTTP/1.1, which handles one request at a time per connection.
  • Recent findings suggest that HTTP/2 to origins is available from all CloudFront edge locations.

Amazon CloudFront now supports HTTP/2 connections to custom origins and VPC origins. HTTP/2 lets CloudFront send many requests over fewer connections to your origin. This means fewer connections and TLS handshakes for your origin to handle, which improves performance for API and agentic workloads, such as AI agents calling MCP servers or mobile and web apps calling backend APIs.

Sources indicate that until now, CloudFront connected to origins only over HTTP/1.1, which handles one request at a time per connection. When traffic spiked, for example when an AI agent made many tool calls at once, CloudFront had to open more origin connections. Each new connection added latency and load. With HTTP/2, those requests share connections, so your origin does less work and responds faster. HTTP/2 is also supported for WebSocket connections that support extended CONNECT. If your origin doesn't support HTTP/2, CloudFront automatically falls back to HTTP/1.1, so you don't need to change anything on your origin.

Recent findings suggest that HTTP/2 to origins is available from all CloudFront edge locations. There is no additional cost for using HTTP/2 to origins. To learn more, visit Origin HTTP version in the CloudFront Developer Guide.
