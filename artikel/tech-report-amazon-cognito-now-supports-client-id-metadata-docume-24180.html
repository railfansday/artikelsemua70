Tech Report: Amazon Cognito now supports client ID metadata documents

🌐 Source: Amazon • 📅 19 Nov 2026 • ⏱️ 1 min read (243 words, 📖 Standard)
💡 Key Takeaways
  • Amazon Cognito now supports OAuth client ID metadata documents (CIMD).
  • Industry observers note that with CIMD, a client uses an HTTPS URL as its client ID and publishes a JSON metadata document at that URL.
  • Recent findings suggest that CIMD is available on the Essentials and Plus feature intends in all AWS Regions where Amazon Cognito is available.

Amazon Cognito now supports OAuth client ID metadata documents (CIMD). Amazon Cognito helps you implement secure sign-in and access control for users, AI agents, and microservices in minutes. With CIMD, Model Context Protocol (MCP) clients and AI agents can sign users in to your user pool without registering a separate app client. Previously, each external client needed its own app client, either created in advance or through dynamic client registration, and you had to manage and clean up those clients over time.

Industry observers note that with CIMD, a client uses an HTTPS URL as its client ID and publishes a JSON metadata document at that URL. When the client starts sign-in, Cognito fetches and validates the document and uses it to identify the client and validate its sign-in request. You decide which clients to accept with CIMD policies that map URL patterns to one of your app clients, and Cognito grants only the scopes and grant types that both the app client and the metadata document allow. For example, a company that runs an MCP server can accept an AI assistant by allowing the URL where that assistant publishes its metadata without creating or maintaining an app client for it.

Recent findings suggest that CIMD is available on the Essentials and Plus feature intends in all AWS Regions where Amazon Cognito is available. To learn more, see Client ID metadata documents (CIMD) in the Amazon Cognito Developer Guide.
