Amazon SageMaker HyperPod extends AMI auto-patching to Slurm and inference on EKS

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Amazon SageMaker HyperPod now automatically patches AMIs on Slurm clusters and introduces a upcoming AMI patching strategy for Amazon EKS clusters that deploy inference workloads. SageMaker HyperPod is purpose-built infrastructure for training and deploying foundation models at scale. Previously, patching a Slurm cluster meant waiting for training runs to finish, scheduling downtime, and upgrading nodes by hand, which could take days of coordination between infrastructure admins and research scientists. Also, auto-patching on Amazon EKS waited for nodes to go idle, which suited training workloads but left nodes serving inference workloads, which rarely go idle, without critical AMI updates.

Now, HyperPod patches both while jobs and models keep running:.

Recent findings suggest that auto-patching (Slurm): HyperPod patches each node only when it is idle, so running jobs aren't disrupted. Teams no longer have to choose between training and security, and can keep clusters secure without coordination between infrastructure admins and research scientists. Each HyperPod AMI has an ImageReleaseVersion that follows semantic versioning (major.minor.patch) across the NVIDIA driver, CUDA, EFA, NCCL, and OS kernel. Auto-patching applies only patch-level updates to the version you select (for example, 1.4.x), so you get security fixes without upgrades that could break your training jobs.

In a recent development, drainFirst patching strategy (Amazon EKS): HyperPod patches nodes that run inference workloads in rolling batches, draining pods while respecting your Pod Disruption Budgets, so your model keeps serving. If a drain times out, you choose whether HyperPod force-evicts the remaining pods for an urgent patch or skips the node to protect a critical model deployment.

In a recent development, when a patch AMI is released, HyperPod schedules the patch 21 days out and notifies you through AWS Health. You can apply it earlier, defer it up to 60 days measured from the patch AMI release date, or turn it off.

Sources indicate that these capabilities are available in all AWS Regions where SageMaker HyperPod is available. To learn more, see Amazon SageMaker HyperPod AMI automatic patching in the user guide.
