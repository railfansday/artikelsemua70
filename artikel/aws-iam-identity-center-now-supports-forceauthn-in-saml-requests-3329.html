AWS IAM Identity Center now supports ForceAuthn in SAML requests

🌐 Source: Amazon • 📅 16 Nov 2026 • ⏱️ 1 min read (250 words, 📖 Standard)

It has been revealed that AWS IAM Identity Center now gives you the option to require workforce consumers to re-authenticate with your external identity provider (IdP) each time their user interactive session expires. By default, when a user's session expires, IAM Identity Center renews it through the user's existing IdP session, and the user isn't prompted to sign in again. For organizations with strict security or compliance requirements that mandate explicit user verification at regular intervals, this automatic renewal may not meet policy requirements.

When you set user re-authentication to Required and a user's user interactive session expires, IAM Identity Center prompts the user to re-authenticate with your external IdP. This helps you enforce stronger sign-in controls for regulated workloads. IAM Identity Center implements this by adding the SAML 2.0 ForceAuthn attribute to the SAML request sent to your IdP.

According to recent reports, you can configure user re-authentication for any IAM Identity Center instance (organization or account) that's connected to an external IdP as its identity source. The setting applies only to service provider initiated sign-ins, where users sign in through your AWS access portal URL. Changes to the user re-authentication setting are logged in AWS CloudTrail, so you can audit when it was turned on or off.

Recent findings suggest that user re-authentication is available in all AWS Regions where IAM Identity Center is available at no additional cost. To learn more, see Require user re-authentication in the AWS IAM Identity Center User Guide.
