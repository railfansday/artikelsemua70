Amazon RDS for Oracle reduces downtime for automatic minor version upgrades and scheduled maintenance

Recent findings suggest that amazon Relational Database Service (Amazon RDS) for Oracle now reduces downtime for automatic minor version upgrades, as well as minor version upgrades and operating system updates scheduled for your maintenance window. Shorter maintenance makes it easier to stay current on the latest Oracle minor versions and operating system updates with less disruption to your applications. If you turned on automatic minor version upgrade, your DB instances benefit automatically.

To apply these upgrades and updates, RDS has to set up fresh resources as part of the maintenance. Previously, RDS set up these resources after the maintenance started, which made your downtime longer. Now, RDS prepares them up to 30 minutes before your maintenance window, while your DB instance keeps serving your workload. When the maintenance window opens, your DB instance is offline for less time because resources required for the maintenance are already prepared. This applies to both Enterprise Edition and Standard Edition 2 DB instances.

It has been revealed that the preparation never blocks or delays your own operations, and your DB instance stays available while RDS prepares. If a change that you make conflicts with the preparation, RDS rolls back the staged resources, and your change goes ahead. If the preparation can't finish, RDS still applies the maintenance in your window, without the preparation. Newly introduced RDS events tell you when the preparation starts, when it finishes, and when it can't finish. RDS for Oracle will continue to introduce improvements that further reduce maintenance downtime.

This capability is available at no additional cost in all commercial AWS Regions and the AWS GovCloud (US) Regions where Amazon RDS for Oracle is available. To learn more, see Maintenance preparation, Amazon RDS event categories and event messages, and Maintaining a DB instance in the Amazon RDS User Guide.
