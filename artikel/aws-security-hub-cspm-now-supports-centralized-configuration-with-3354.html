AWS Security Hub CSPM now supports centralized configuration with AWS Organizations declarative policies

🌐 Source: Amazon • 📅 13 Nov 2026 • ⏱️ 1 min read (198 words, 📖 Standard)
💡 Key Takeaways
  • Recent findings suggest that AWS Security Hub CSPM now supports AWS Organizations declarative policies.
  • Policies can apply broadly to every account and Region, or target specific account and Region combinations.
  • Industry observers note that declarative policies are now the recommended way to manage Security Hub CSPM across an organization.

Recent findings suggest that AWS Security Hub CSPM now supports AWS Organizations declarative policies. You can use them to enable Security Hub CSPM across all accounts and Regions in your organization and to define which security standards and controls are enabled.

Policies can apply broadly to every account and Region, or target specific account and Region combinations. Declarative policies help keep each account's configuration aligned with its attached policy, which helps prevent configuration drift. You can also apply them automatically to fresh accounts, so each account starts with a baseline configuration as soon as it's created.

Industry observers note that declarative policies are now the recommended way to manage Security Hub CSPM across an organization. They align with how other security services, such as Amazon GuardDuty, Amazon Inspector, and AWS Security Hub allow customers to manage configuration of the service. They also provide more flexibility, such as configuring Region-specific settings. You can continue to use central configuration until you're ready to migrate. When you are, use the migration process in the Security Hub CSPM console. It converts your existing central configuration policies into declarative policies and applies them to the appropriate accounts and regions.
