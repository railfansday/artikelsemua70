📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Today, Amazon API Gateway announces API Portal, a new feature that discovers, governs, and documents the APIs and AI endpoints behind Amazon API Gateway, Application Load Balancer, and Amazon CloudFront across your AWS organization.

According to recent reports, many organizations can't see which APIs are running, which were never registered, which are no longer maintained, and which lack protection. API Portal builds a continuously updated inventory using AWS-side traffic logs and service configuration records, with nothing to install, no logs to forward, and no traffic to reroute, for a single account or your entire AWS organization.

Sources indicate that every discovered API starts as a shadow API until you choose to manage it. API Portal labels each API as public or private and identifies AI endpoints, including MCP servers, A2A servers, and LLM endpoints. For managed APIs, it flags those that stop receiving traffic or lose their owner and evaluates security posture against best practices such as authentication, throttling, and AWS WAF protection. With AWS WAF API Security, it also highlights the security events detected per API.

It has been revealed that you can publish any managed API in a documentation portal for internal teams or external partners, with your branding, Amazon Cognito access control, and interactive Try it pages. If you already use API Gateway Portals, your portals continue to work and are now managed from the Documentation Portals section of API Portal.

API Portal is available in 32 AWS Regions; see the Amazon API Gateway FAQ and pricing pages for details.
