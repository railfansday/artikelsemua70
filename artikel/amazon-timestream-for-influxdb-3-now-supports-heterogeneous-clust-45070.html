Amazon Timestream for InfluxDB 3 now supports heterogeneous clusters

🌐 Source: Amazon • 📅 27 Nov 2026 • ⏱️ 1 min read (236 words, 📖 Standard)
💡 Key Takeaways
  • Amazon Timestream for InfluxDB 3 now supports heterogeneous clusters, which let you assign a different instance size to each node role in an InfluxDB 3 Enterprise cluster.
  • Time series workloads rarely load every part of a database the same way.
  • There is no additional charge, and you pay the standard price for each node at the size you select.

Amazon Timestream for InfluxDB 3 now supports heterogeneous clusters, which let you assign a different instance size to each node role in an InfluxDB 3 Enterprise cluster. You can size the writer, reader, and compactor roles independently. You set the size for each role when you create a cluster or add nodes to an existing cluster, using the Amazon Timestream console, the AWS Command Line Interface (CLI), or the AWS SDKs.

Time series workloads rarely load every part of a database the same way. Queries need memory for the query cache, writes are gated by durable flushes to object storage, and compaction needs vCPUs to merge files in the background. Because every node previously ran one instance size, scaling a single role meant scaling all of them and paying for headroom on nodes already sized correctly. You can now place reader nodes on a larger size for a bigger cache or more complex queries while keeping writer nodes smaller, or give the compactor more vCPUs without changing the rest of the cluster.

There is no additional charge, and you pay the standard price for each node at the size you select. Heterogeneous clusters are available for InfluxDB 3 Enterprise clusters in all AWS Regions where Amazon Timestream for InfluxDB is available. To get started, open the Amazon Timestream console. For more information, see the Amazon Timestream for InfluxDB documentation and pricing page.
