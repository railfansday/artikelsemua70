Amazon RDS now supports fast storage volume initialization

🌐 Source: Amazon • 📅 18 Nov 2026 • ⏱️ 1 min read (280 words, 📖 Standard)

In a recent development, amazon RDS now initializes storage volumes faster when you perform a point-in-time restore (PITR), create a read replica, or convert a Single-AZ instance to Multi-AZ. Each of these operations creates storage volumes from a snapshot, and the data blocks are downloaded from Amazon S3 before you can access them. With fast storage volume initialization, you get a fully performant DB instance in a predictable amount of time.

According to recent reports, previously, the initialization rate varied with your workload and with which blocks were accessed. As there was no dedicated bandwidth, so you could see increased I/O latency and had no way to tell when an instance would reach full performance. Now, each database instance is initialized at up to 4 TiB per hour, across every gp3 and io2 storage volume attached to the instance. If concurrent initialization across your account exceeds the available bandwidth, the remaining blocks initialize on a best-effort basis, so initialization is never slower than today. Your DB instance stays available and usable while initialization runs.

It has been revealed that fast storage volume initialization is enabled by default and no action is required. To follow progress, use the StorageOperationStatus and StorageOperationPercentProgress fields in the Amazon RDS console, the DescribeDBInstances API, the AWS Command Line Interface (CLI), or AWS SDKs.

According to recent reports, this capability is available at no additional cost for RDS for MariaDB, RDS for MySQL, RDS for PostgreSQL, RDS for Db2, RDS for Microsoft SQL Server, and RDS for Oracle, in all commercial AWS Regions and the AWS GovCloud (US) Regions. To learn more, see Amazon RDS storage in the Amazon RDS User Guide.
