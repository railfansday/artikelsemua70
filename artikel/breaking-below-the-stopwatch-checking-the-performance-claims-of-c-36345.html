Breaking: Below the Stopwatch: Checking the Performance Claims of Coding Agents in the Kernel

🌐 Source: Arxiv • 📅 26 Nov 2026 • ⏱️ 1 min read (223 words, 📖 Standard)

arXiv:2611.31460v1 Announce Type: cross Abstract: Coding agents open many pull requests (PRs) that claim to make software faster. Most such claims also give a reason, such as "cache the result" or "read the file once". A stopwatch can show that code got faster, but not that it got faster for the stated reason. We present Below, a pipeline that checks these reasons at the kernel level. From 1,343 runtime-performance PRs in the AIDev dataset, Below extracts the mechanism each PR claims and maps it to the kernel and hardware signals that must change if the claim is true. A build agent that never sees the claim rebuilds the code before and after each PR. Below then measures both versions with plain timing runs, hardware counters and LTTng kernel traces. Most claims are not measured: 57.3% of the PRs offer only reasoning or no evidence, and only 31.4% state an effect size. Of 82 analyzed PRs, 32 ran faster, 28 showed no clear change and 22 ran slower. The expected signal of the claimed mechanism appeared in 34 PRs (20 in kernel-trace signals alone), and 42 PRs also changed their output. Kernel signals move about 1.7 times as often for a faster PR's claimed mechanism as for mechanisms it did not claim; the instruction count barely separates them (1.15 times).
