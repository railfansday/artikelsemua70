Latest Update: AWS Network Firewall now supports context-aware rules with AWS Transit Gateway-attached firewalls

Recent findings suggest that AWS Network Firewall attached to AWS Transit Gateway now allows you to use context-aware rules in your firewall policy. Network Firewall is a managed firewall and intrusion prevention service that inspects and filters traffic across your virtual private clouds (VPCs). With context-aware rules, you write rules that reference context from VPC resources instead of IP addresses. This makes it easier to apply consistent security controls as your organization grows. Existing rules automatically cover upcoming workloads, so you don't need to patch rules manually.

Recent findings suggest that context-aware rules match traffic using VPCs, subnets, security groups, and Transit Gateway attachment identifiers, collectively known as context identifiers. You can reference context identifiers in a rule's source for any protocol, and in its destination for TCP-based protocols such as HTTP, TLS, and SSH. Flow and alert logs include context identifiers, so you can investigate activity based on context.

According to recent reports, context-aware rules are available at no additional charge in all commercial and AWS GovCloud (US) Regions. For a full list of supported Regions, see the AWS Capabilities by Region page.

To learn more, see the AWS Network Firewall product page and documentation.
