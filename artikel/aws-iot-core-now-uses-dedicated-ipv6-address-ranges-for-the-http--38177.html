AWS IoT Core now uses dedicated IPv6 address ranges for the HTTP rule action

🌐 Source: Amazon • 📅 25 Nov 2026 • ⏱️ 1 min read (280 words, 📖 Standard)

AWS IoT Core can now send traffic to HTTPS endpoints within a dedicated, published IPv6 address range. This launch enables you to configure your HTTPS endpoints to accept requests only from AWS IoT Core and block all other traffic, thereby reducing your endpoint's exposure to public internet.

AWS IoT Core is a fully managed service that securely connects IoT devices at scale to the AWS cloud and routes IoT device data to AWS and third-party services. AWS IoT Core's HTTP rule action delivers IoT device data to any HTTPS endpoint, such as your application servers, on-premises systems, or partner services. With this launch, you can choose from AWS IoT Core's published IPv6 range, and add the fixed IPv6 range to an Amazon API Gateway resource policy, a security group, or your firewall rules. Your HTTPS endpoints will then accept traffic only from AWS IoT Core, giving you network layer control over who can reach your endpoint.

Industry observers note that to get started, configure your HTTPS endpoint destination to be reachable only over IPv6 by publishing AAAA DNS records (and removing the A DNS records). This allows IoT Core's HTTP rule action to use only IPv6 addresses when sending data to your HTTP destination. Then allow AWS IoT Core's published IPv6 range for your Region, and create or update your HTTP rule action with the endpoint destination. Dedicated IPv6 ranges are available at no additional charge in all AWS Global Regions where AWS IoT Core is available, including AWS GovCloud (US). To find the range for your Region, see Restricting HTTP action traffic to the rules engine IPv6 ranges in the AWS IoT Core Developer Guide.
