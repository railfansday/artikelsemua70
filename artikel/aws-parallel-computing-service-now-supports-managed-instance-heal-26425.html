AWS Parallel Computing Service now supports managed instance health checks

AWS Parallel Computing Service (AWS PCS) now supports instance health checks, which can find hardware faults and software problems on accelerated instances beyond what Amazon EC2 detects today. For example, a fault such as an uncorrectable GPU memory error can stop or slow every job on a compute node. Instead of losing the next job to the same bad GPU, AWS PCS can take the compute node out of scheduling and replace its instance with a latest one.

Recent findings suggest that you can turn on instance health checks for a compute node group in the AWS PCS console, AWS CLI, or AWS SDKs. Health monitoring watches NVIDIA GPUs, AWS Neuron devices, and Elastic Fabric Adapter (EFA) devices continuously, including while jobs run. Optional deep health checks run NVIDIA Data Center GPU Manager (DCGM) diagnostics each time an instance starts, from the GPU software stack to stress tests of the hardware, so a faulty GPU can be caught before a job lands on it. You choose what AWS PCS does next: replace the instance, isolate the compute node for investigation, or only report the fault. You can see each result and repair action in Slurm, alongside the compute node's other status information.

AWS PCS is a managed service that simplifies running and scaling high performance computing (HPC) workloads on AWS using Slurm. You can build complete, elastic environments that integrate compute, storage, networking, and visualization tools, and the service manages cluster updates and provides built-in observability.

To learn more, see Detecting and repairing hardware faults with instance health checks in the AWS PCS User Guide. Instance health checks require Slurm 26.05 or later and an AMI with AWS PCS agent 1.6.0-1 or later, and are available in all AWS Regions where AWS PCS is available.
