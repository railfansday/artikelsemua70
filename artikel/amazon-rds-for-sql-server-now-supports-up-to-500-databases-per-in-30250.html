Amazon RDS for SQL Server now supports up to 500 databases per instance

🌐 Source: Amazon • 📅 24 Nov 2026 • ⏱️ 1 min read (209 words, 📖 Standard)
💡 Key Takeaways
  • Amazon Relational Database Service (Amazon RDS) for SQL Server now supports up to 500 databases per DB instance, up from the previous limit of 100.
  • You can use this feature to consolidate databases on fewer DB instances.
  • This feature is available in all AWS Regions where Amazon RDS for SQL Server is available.

Amazon Relational Database Service (Amazon RDS) for SQL Server now supports up to 500 databases per DB instance, up from the previous limit of 100. This higher density helps software as a service (SaaS) providers, multi-tenant applications, and other customers who run many databases on a DB instance. Previously, these customers had to spread their databases across several DB instances.

You can use this feature to consolidate databases on fewer DB instances. This simplifies management, reduces the number of DB instances to monitor and patch, and lowers license and infrastructure costs. The 500-database limit applies to DB instances with 4 or more vCPUs (xlarge and larger, excluding burstable instance classes) on all SQL Server versions that Amazon RDS supports. It's available for Single-AZ deployments of Enterprise, Enterprise Developer, Standard, Standard Developer, and Web editions, and for Multi-AZ deployments of Enterprise, Enterprise Developer (using Always On Availability Groups), and Web edition.. Multi-AZ deployments using Database Mirroring, Multi-AZ deployments of Standard Edition, and smaller instances keep their current limits.

This feature is available in all AWS Regions where Amazon RDS for SQL Server is available. To learn more, see Amazon RDS for Microsoft SQL Server User Guide. For pricing details, see Amazon RDS for SQL Server Pricing.
