In a recent development, amazon OpenSearch Service now supports distributed joins, high-cardinality aggregations, and OpenSearch query DSL on the new engine. Observability data often spans logs, traces, and agent traces. Engineers and their AI agents must connect these datasets to determine what failed, where it failed, and who was affected.

With Piped Processing Language (PPL) or SQL, engineers and agents can query multiple petabytes to connect an error log to its trace and enrich telemetry with service ownership or deployment metadata in one query. High-cardinality aggregations help you measure incident impact across millions of distinct hosts, users, or tenants. Because the fresh engine distributes joins and aggregations across data nodes, you don’t need to copy related data into a single index.

In a recent development, routing key support keeps related documents on the same shard, so lookups and joins on that key stay fast. The new engine also supports OpenSearch query DSL, so applications, alerts, and integrations that send query DSL get its cost and performance benefits for supported analytics workloads without rewrites.

Recent findings suggest that these features are available on OpenSearch 3.9, at no additional charge, in the following AWS Regions: US East (N. Virginia), US East (Ohio), US West (Oregon), Canada (Central), Asia Pacific (Mumbai), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Tokyo), Europe (Frankfurt), Europe (Ireland), Europe (London), and Europe (Spain). To get started, create or upgrade a domain to OpenSearch 3.9 with the latest engine. To learn more, see the documentation.
