Industry News: AgentCore runtime instances now support privileged mode

🌐 Source: Amazon • 📅 18 Nov 2026 • ⏱️ 1 min read (184 words, 📖 Standard)
💡 Key Takeaways
  • In a recent development, amazon Bedrock AgentCore runtime instances now support privileged mode, which lets your agents install system-level software and run nested containers.
  • It has been revealed that you turn on privileged mode when you create or update an agent runtime that runs on runtime instances.
  • Privileged mode is available in all AWS Regions where AgentCore runtime instances are available.

In a recent development, amazon Bedrock AgentCore runtime instances now support privileged mode, which lets your agents install system-level software and run nested containers. Runtime instances run your agents on Amazon EC2 instances while AgentCore handles provisioning, patching, scaling, and lifecycle management.

It has been revealed that you turn on privileged mode when you create or update an agent runtime that runs on runtime instances. For example, a coding agent can start its service dependencies, such as Postgres and Redis, as containers and run its integration tests against them. A code-modernization agent can install the compilers and libraries that a migration needs. A session that runs a privileged agent runs only that agent, so elevated privileges stay with one agent on its instance. Agents that don't use privileged mode keep the default standard mode, so existing agents don't change. Standard mode suits most agents. Use privileged mode only if your agent needs to install system-level software or run containers.

Privileged mode is available in all AWS Regions where AgentCore runtime instances are available.
