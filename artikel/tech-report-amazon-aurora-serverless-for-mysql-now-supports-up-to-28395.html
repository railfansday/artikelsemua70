Tech Report: Amazon Aurora serverless for MySQL now supports up to 384 ACUs

🌐 Source: Amazon • 📅 23 Nov 2026 • ⏱️ 1 min read (281 words, 📖 Standard)

It has been revealed that amazon Aurora serverless now supports database capacity of up to 384 Aurora Capacity Units (ACUs) for Aurora MySQL-Compatible Edition, a 50% increase from the previous maximum of 256 ACUs. Each ACU provides approximately 2 gibibytes (GiB) of memory with corresponding CPU and networking, so a single Aurora serverless database can now scale up to 768 GiB of memory. When the workload completes, Aurora serverless automatically scales down to zero. This makes Aurora serverless especially well-suited for agentic AI applications, which typically have bursts of activity, long idle windows, and unpredictable traffic patterns. Aurora serverless handles all of it automatically, scaling capacity with your agents, so you only pay for what you use. With 384 ACU support, customers can now use Aurora serverless for even more demanding workloads while continuing to scale down to zero when not in use, paying only for the capacity consumed. For latest clusters, select a supported Aurora MySQL engine version and set your maximum capacity up to 384 ACUs. For existing clusters on Platform Version 4, simply modify the cluster to update the maximum capacity setting (and the engine version if needed). There will be no downtime if your database is already on Platform Version 4. For existing clusters on older platform versions, upgrade to Platform Version 4 through a pending maintenance action. 384 ACU support is available for Aurora MySQL versions 3.14 and 8.4.10, running on Platform Version 4. To learn more, see Aurora serverless capacity in the Amazon Aurora User Guide. For pricing details and Region availability, visit Amazon Aurora Pricing. To get started, create or modify an Aurora serverless database in the AWS Management Console.
