AWS Parallel Computing Service now supports Split Cost Allocation Data

Industry observers note that starting today, customers can receive granular cost visibility for AWS Parallel Computing Service (AWS PCS) in the AWS Cost and Usage Reports (CUR), enabling you to analyze, optimize, and chargeback costs for your Slurm jobs. With AWS Split Cost Allocation Data for AWS PCS, customers can now allocate costs to individual teams and projects based on how jobs request and consume shared EC2 CPU, GPU, and memory resources.

AWS PCS is a managed service that makes it easier for you to run and scale your high performance computing (HPC) workloads and build scientific and engineering models on AWS using Slurm. With Split Cost Allocation Data for AWS PCS, you get granular visibility into job-level costs based on compute and memory utilization. You can attribute cost to an individual job and aggregate the cost by job, user, Slurm account, queue, compute node group, node, and cluster. You can also identify capacity that wasn't allocated to any job, such as idle cores or nodes waiting for work. This helps you find opportunities to right-size your clusters and minimize inefficiencies.

This feature is available in all AWS commercial regions where AWS PCS is available. It requires Slurm version 25.11 or later. To start receiving AWS PCS Slurm job level cost data in the AWS CUR, visit AWS Cost and Usage Reports, Understanding Split Cost Allocation Data and the AWS PCS User Guide.
