According to recent reports, today, AWS revealed the general availability of Amazon OpenSearch Memory, a new serverless capability in Amazon OpenSearch Service for adding persistent memory to AI agents. OpenSearch Memory stores agent interactions as searchable events, derives useful memories, and retrieves relevant context across sessions, so agents can recall prior decisions, earlier interactions, and user preferences without replaying the full conversation history to the model. Customers can give agents long-term memory without provisioning infrastructure or building separate extraction, indexing, consolidation, and retrieval systems.

Sources indicate that openSearch Memory stores the original events verbatim, makes them searchable within seconds, and asynchronously derives structured memories. It manages the full memory lifecycle, including extraction, embedding, indexing, consolidation (adding, updating, or skipping memories as upcoming information arrives), and retrieval using keyword, semantic, and hybrid search. Customers control access with AWS Identity and Access Management (IAM) for each memory store, with actor and session scoping, and can set expiration periods for events and memories. Because it is serverless, there are no clusters to provision, instance types to choose, or indexes to create, and capacity for extraction and search scales automatically.

Recent findings suggest that amazon OpenSearch Memory is available today in US East (N. Virginia, Ohio), US West (Oregon), Europe (Frankfurt), and Asia Pacific (Tokyo) Regions. For pricing details about Amazon OpenSearch Memory, visit the pricing page.

It has been revealed that to learn more about Amazon OpenSearch Memory, see the technical documentation and launch blog. You can get started by visiting the technical launch blog that details how to add persistent memory to your agents with Amazon OpenSearch Memory.
