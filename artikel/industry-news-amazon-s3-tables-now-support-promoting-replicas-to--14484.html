It has been revealed that amazon S3 Tables replication now lets you make a read-only replica of your Apache Iceberg table a standalone, writable table with a single API call. S3 Tables replication keeps read-only replica tables in sync with your source tables across table buckets, AWS Regions, and accounts. Instead of copying a replica into a new table, you can promote it in place to move writes to another Region.

Industry observers note that when you disassociate a replica from replication, the standalone table keeps its namespace and table name, so your queries and pipeline code carry over when you point your applications at it. The promoted table then works like an S3 table you created, and you can use it as a source for newly introduced replicas.

In a recent development, this capability is available in all AWS Regions where S3 Tables replication is supported. You can use the AWS Management Console, AWS CLI, AWS SDKs, or S3 Tables API. For pricing details, visit the Amazon S3 pricing page. To learn more, see the S3 Tables overview page and documentation.
