Amazon API Gateway REST APIs now support JWT authorizers

🌐 Source: Amazon • 📅 17 Nov 2026 • ⏱️ 1 min read (181 words, 📖 Standard)
💡 Key Takeaways

  • It has been revealed that you can define one or more issuers, the audiences accepted for each, the signing algorithms you permit, and any additional claims a token may present.
  • Industry observers note that the JWT authorizer works on Regional, edge-optimized, and private REST APIs, and is available in all commercial AWS Regions and the AWS GovCloud (US) Regions.

Amazon API Gateway now offers a native JWT authorizer for REST APIs, a newly introduced authorizer type that validates JSON Web Tokens directly in the gateway. Until now, validating tokens from an OpenID Connect or OAuth 2.0 identity provider other than Amazon Cognito required a Lambda authorizer. You now configure token validation instead of writing and operating code for it.

It has been revealed that you can define one or more issuers, the audiences accepted for each, the signing algorithms you permit, and any additional claims a token may present. API Gateway verifies each token's signature, issuer, audience, expiry, and claims on every request. You can attach one authorizer to many methods and require different scopes on each. This fits machine-to-machine APIs, mobile and web backends, and multi-tenant APIs that accept tokens from several identity providers.

Industry observers note that the JWT authorizer works on Regional, edge-optimized, and private REST APIs, and is available in all commercial AWS Regions and the AWS GovCloud (US) Regions. To get started, see Amazon API Gateway documentation and AWS blog post.
