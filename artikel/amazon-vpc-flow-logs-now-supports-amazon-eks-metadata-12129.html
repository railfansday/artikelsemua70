Amazon VPC Flow Logs now supports Amazon EKS metadata

🌐 Source: Amazon • 📅 19 Nov 2026 • ⏱️ 2 min read (320 words, 📖 Standard)

In a recent development, amazon VPC Flow Logs now adds Amazon Elastic Kubernetes Service (Amazon EKS) metadata to flow log records. Each record identifies the pod that sent or received the traffic, along with its cluster, namespace and labels. This makes it faster to investigate security events, understand traffic patterns, and troubleshoot network challenges in your EKS clusters, without running monitoring software on your nodes.

Industry observers note that amazon EKS runs pods on Amazon EC2 instances, called nodes, and many pods can share one node's network interfaces. Previously, flow log records revealed the network interface and IP address for each flow, not the pod behind it. Pods are short-lived, so by the time you investigated unexpected traffic, that IP address could belong to a different pod. To trace traffic back to the right pod, teams built custom tools or ran monitoring software on every node. Now, each record names the pod that sent or received the traffic, so one log gives you both VPC and Kubernetes context. For example, if a pod sends unexpected traffic to a database in your VPC, the record highlights the pod and its namespace, even after that pod is replaced.

Sources indicate that to get started, create a flow log for your cluster's VPC or subnets, and add the EKS fields to the log format. You don't need to change your cluster or applications. The fields are available for pods on Amazon EC2 instances, including EKS Auto Mode, managed node groups and self-managed nodes, that use the Amazon VPC CNI plugin for Kubernetes. Logs go to the same destinations as before, so your existing analytics tools keep working. EKS metadata is available at no additional charge. Standard VPC Flow Logs charges for log delivery and storage still apply. This feature is supported in all AWS Regions where Amazon EKS is available. For more information, visit the Amazon VPC Flow Logs.
