AWS Security Hub now infers resource criticality from installed software and usage

🌐 Source: Amazon • 📅 17 Nov 2026 • ⏱️ 1 min read (194 words, 📖 Standard)

Sources indicate that today, AWS Security Hub adds installed software and resource usage as signals for resource criticality, which indicates how important a resource is to your business. Security Hub uses criticality to rank exposure findings, so that central security teams can prioritize the exposures that affect their most important resources.

In a recent development, security Hub already infers criticality from resource tags and names, but inconsistently tagged resources often have an Unknown criticality, which makes their exposures harder to prioritize. With installed software and resource usage as additional signals, more of your resources receive a meaningful criticality with no tagging or configuration required. For example, an EC2 instance that runs a database engine and serves steady traffic receives a higher criticality than an instance that runs only monitoring agents and sits idle.

These signals are included with the Security Hub Essentials plan at no additional cost and require no latest enablement. To learn more, see Resources in Security Hub in the AWS Security Hub User Guide and the AWS Security Hub product page.
