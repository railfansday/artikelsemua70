It has been revealed that long before they run out of compute or power, AI applications hit another wall: running out of IP addresses. A single AI deployment often requires a vast address space to support everything from thousands of accelerator nodes, scaling inference replicas, bursting Ray workers and pipelines, pod sidecars, and services like vector databases. Running a dual stack — IPv6 behind a private IPv4 space — can help, but only to a point, because the private IPv4 space has often already been exhausted across existing networks.

In a recent development, to help, today, we're announcing single-stack IPv6 on Google Kubernetes Engine (GKE), allowing you to run both nodes and pods on IPv6, without private IPv4 addresses. Single-stack IPv6 is available in preview for Cloud TPU v6e and CPU node pools, including Axion, and works with DNS64/NAT64 to reach IPv4 endpoints.

Nodes and pods run IPv6-only across Cloud TPU v6e and CPU-based node pools, with no private IPv4. Workloads reach Google Cloud APIs over native IPv6 and IPv4-only endpoints through DNS64/NAT64.

The availability of single-stack IPv6 in GKE is a game-changer for large AI deployments. Consider the following features and benefits that it brings to the table:.

According to recent reports, 1. No private IPv4 required for nodes or podsNodes and pods use IPv6 exclusively. Without the RFC 1918 footprint that governs private IPv4 address spaces, clusters avoid conflicts with on-premises networks, peered VPCs, or adjacent clusters.

2. IPv4 interoperability with DNS64/NAT64You enable DNS64 on the VPC, and NAT64 on a regional Cloud NAT gateway, allowing pods to transparently reach IPv4-only endpoints, registries, and dataset hubs — refer to the documentation to learn how to configure DNS64 and set up Cloud NAT.

Recent findings suggest that 3. Massive address space per nodeEach node receives a /112 pod range (65,536 addresses), so IP address capacity no longer limits how high your clusters, nodes, or pods can scale. Standard GKE maximum-pods-per-node limits still apply.

Recent findings suggest that 4. Broad accelerator and compute supportWe designed single-stack IPv6 in GKE with the goal of supporting a range of accelerators and general compute families. At preview, it supports Cloud TPU v6e (Trillium), plus E2, N1, N2, N2D, N4, C3, C3D, C4, C4D, C4A, and Z3 machine families, with support for additional accelerators and machine families coming soon.

5. Direct workload observabilityEvery pod has a unique IPv6 address without having to run NAT inside the cluster, simplifying telemetry, network policies, and debugging.

According to recent reports, single-stack IPv6 removes private IPv4 address limits without additional data plane overhead. In our internal testing, we saw the following performance characteristics:.

Pod lifecycle: Burst pod scheduling and CNI sandbox setup performed at parity with IPv4.

Networking: Inter-node TCP/UDP latency and multi-stream pod-to-pod throughput matched IPv4.

Services and DNS: eBPF service load balancing and NodeLocalDNS indicated no measurable overhead compared to standard IPv4.

Single-stack IPv6 is available now in preview on GKE version 1.37.1-gke.3020000.
