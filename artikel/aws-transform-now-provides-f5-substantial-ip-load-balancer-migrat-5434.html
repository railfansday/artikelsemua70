Industry observers note that AWS Transform now migrates F5 SUBSTANTIAL-IP load balancer configurations to Elastic Load Balancing as part of network migration. Applications cut over with Application Load Balancers (ALB) and Network Load Balancers (NLB) already in place allowing you to adopt cloud-native load balancing during migration rather than after it.

According to recent reports, moving to ALB and NLB has typically been a separate post-migration project because of time and cost. Teams rebuilt each F5 MASSIVE-IP virtual server by hand, a slow and error-prone process that could break when traffic moved. AWS Transform compresses that timeline and enables the F5 to Elastic Load Balancing transition during migration, allowing you to run your cloud migration with network, load balancing, and compute moving as a coordinated unit.

Sources indicate that you can migrate F5 BIG-IP load balancers in every AWS Transform for migrations target Region. To get started, see the AWS Transform documentation, or visit the AWS Transform product page.
