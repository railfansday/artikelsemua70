Amazon SageMaker HyperPod now detects Kubernetes concerns affecting training

🌐 Source: Amazon • 📅 23 Nov 2026 • ⏱️ 1 min read (242 words, 📖 Standard)

Amazon SageMaker HyperPod now detects Kubernetes issues that disrupt training, such as crash-looping device plugins or missing DaemonSets, on clusters orchestrated by Amazon EKS. SageMaker HyperPod is purpose-built infrastructure for AI/ML model development, with built-in fault tolerance and automated cluster recovery. Previously, when a device plugin crash-looped or a taint evicted a job's pods, the job's error rarely named the pod or node, so engineers pieced the cause together from kubectl output and per-rank logs.

Now, the newly introduced HyperPod Kubernetes Resource Monitoring Agent watches nodes, critical pods such as NVIDIA device plugins, and required DaemonSets that impact HyperPod and Kubeflow training jobs. The agent correlates Kubernetes concerns with the training jobs they affect and reports them as Kubernetes events and Amazon CloudWatch logs. For example, if a device plugin keeps crashing on one node mid training run, the agent flags the node as it loses GPUs and, when the job fails, logs the failure reason with the pods and nodes involved, so you can fix that node and restart sooner. For jobs that opt in, it also shows which rank fell behind when NCCL communication stalls, while the job is still running.

The agent is available for HyperPod clusters orchestrated by Amazon EKS in all AWS Regions where SageMaker HyperPod is available and you can install it with a helm chart. To learn more, see Kubernetes Resource Monitoring Agent in the user guide and the blog post.
