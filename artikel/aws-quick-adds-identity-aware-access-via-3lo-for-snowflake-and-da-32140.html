AWS Quick adds identity-aware access via 3LO for Snowflake and Databricks structured data sources

🌐 Source: Amazon • 📅 23 Nov 2026 • ⏱️ 1 min read (156 words, 📖 Standard)
💡 Key Takeaways
  • AWS Quick now supports three-legged OAuth (3LO) with end-user permissions for Snowflake and Databricks.
  • It has been revealed that to get started, an administrator adds an OAuth client application in Quick account settings.
  • This feature is available in Quick regions here.

AWS Quick now supports three-legged OAuth (3LO) with end-user permissions for Snowflake and Databricks. When end customers in AWS Quick consume Chat, interactive dashboards, or Apps, queries run using their own Snowflake or Databricks identity. Governance policies configured in Snowflake or Databricks Unity Catalog, including applicable row- and column-level controls and access to tables and views, are enforced by the source platform without requiring teams to recreate those policies in Quick.

It has been revealed that to get started, an administrator adds an OAuth client application in Quick account settings. Data curators then create a Snowflake or Databricks data source, choose 3LO, and turn on trusted identity propagation so each user's identity is passed to the source. End-user permissions through 3LO are supported only for DirectQuery datasets.

This feature is available in Quick regions here. To learn more, see Using Snowflake with AWS Quick and Setting up identity enforcement with Databricks 3LO.
