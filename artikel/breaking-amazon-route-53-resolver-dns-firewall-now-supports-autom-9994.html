📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Amazon Route 53 Resolver DNS Firewall now automatically generates domain allow-lists from your VPCs' observed DNS query traffic, helping you enforce least-privilege DNS access and reduce the risk of DNS-based data exfiltration.

Previously, implementing a least-privilege model required security teams to manually analyze DNS query logs to identify the domains their VPCs depend on before deploying allow-list rules. This created operational overhead and delayed enforcement of a deny-by-default (walled-garden) posture.

According to recent reports, with automated allow-list generation, DNS Firewall analyzes DNS query traffic using a lookback window configurable from 1 hour to 7 days to create an allow-list of observed domains. It then continuously monitors DNS queries and flags newly observed domains, so you can review them before adding them to the allow-list. You can deploy the rule across multiple VPCs and accounts using AWS Firewall Manager or Route 53 Profiles.

It has been revealed that this capability is available at no additional cost to DNS Firewall Advanced customers, in all AWS Regions where Route 53 DNS Firewall is supported, except in AWS GovCloud (US) and Amazon Web Services China Regions. To get started, use the Route 53 DNS Firewall console, AWS CLI, or API.

To learn more, visit the Amazon Route 53 Resolver DNS Firewall product page and the Route 53 DNS Firewall Developer Guide.
